============ THE SEVEN ORDERS OF GROWTH ============
  Basic operations performed by an algorithm of each class, for input size n.
  This is the whole argument for asymptotic analysis in one table: the classes
  separate so violently that constant factors stop mattering.

     n      O(1)     O(lg n)        O(n)     O(n lg n)        O(n^2)        O(2^n)         O(n!)
     1         1           0           1             0             1             2             1
     2         1           1           2             2             4             4             2
     4         1           2           4             8            16            16            24
     8         1           3           8            24            64           256         40320
    16         1           4          16            64           256         65536      2.09e+13
    32         1           5          32           160          1024      4.29e+09      2.63e+35
    64         1           6          64           384          4096      1.84e+19      1.27e+89
   128         1           7         128           896         16384      3.40e+38     3.86e+215

  Reading the table:
    constant      doubling n changes nothing at all.
    logarithmic   doubling n adds ONE step; 128 items cost 7 probes, not 128.
    linear        doubling n doubles the work - the natural cost of reading input.
    linearithmic  doubling n slightly more than doubles it (+n extra); this is the
                  ceiling for any sorting algorithm that only compares keys.
    polynomial    doubling n multiplies the work by 2^k for n^k; still tractable.
    exponential   ADDING ONE to n doubles the work; tractable only for tiny n.
    factorial     adding one to n multiplies the work by n; 20! already exceeds the
                  number of seconds since the Big Bang at one operation per ns.

===== EVIDENCE THAT THE LIS ALGORITHM IS LINEARITHMIC =====
  If the cost were linear, probes/n would be constant.
  If it is linearithmic, probes/n grows like lg n while probes/(n lg n) settles.

         n        probes    probes/n probes/(n lg n)    time(ms)  time/(n lg n) ns
     10000         68967       6.897          0.5190        0.44            3.3482
     20000        148268       7.413          0.5189        0.86            2.9984
     40000        317607       7.940          0.5194        1.56            2.5570
     80000        673406       8.418          0.5168        3.27            2.5079
    160000       1433438       8.959          0.5182        6.89            2.4927
    320000       3018932       9.434          0.5159       15.17            2.5929
    640000       6374468       9.960          0.5164       32.16            2.6054
   1280000      13373105      10.448          0.5150       68.51            2.6383

  probes/n climbs steadily (it is tracking lg n) while probes/(n lg n)
  flattens out: the cost is Theta(n lg n), not Theta(n).

  Factorial growth has a signature: t(n)/t(n-1) tends to n itself.

    5           120           120          0.00               -         5
    6           720           720          0.00            3.58         6

    8         40320         40320          0.24            8.43         8

   10       3628800       3628800         26.52           11.42        10
   11      3.99e+07      39916800        322.80           12.17        11

  The ratio column tracks n, so each extra attraction multiplies the work
  by about n. Extrapolating, n = 20 would need roughly 2.4e18 tours: at one
  billion tours per second that is about 77 years.

  --- COMPARATIVE STUDY : Held-Karp O(n^2 2^n) on the same data ---
    n   brute force(ms)     Held-Karp(ms)    same answer?

   11            319.50              0.38             yes

  Held-Karp is still exponential, but 2^n grows far more slowly than n!,
  which is why it remains usable where enumeration has already collapsed.
